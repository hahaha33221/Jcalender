# 회원별 개인 프로젝트 전환 계획

작성일: 2026-11-15 · 대상: Jcalender (사이트 · 맥 Dock 앱 · 안드로이드 앱 · VPS 서버)

---

## 1. 개요

- **목적**: 로그인하는 사람마다 Jcalender 를 "자기만의 프로젝트"로 쓰게 한다. 가입부터 화면 구성, 데이터, AI 사용량, 알림까지 각자 독립적으로 시작하고 꾸리고 관리한다.
- **지금 상태 한 줄 요약**: 데이터 저장은 이미 사람마다 나뉘어 있다. 하지만 **화면 구성(영역 · 카테고리)과 운영 방식이 관리자 한 사람 기준**으로 되어 있어서, 다른 사람은 "관리자가 열어 준 만큼만 쓰는 손님"에 가깝다.
- **방향**: 관리자가 정해 주던 것을 각 회원이 직접 정하게 바꾸고, 관리자 설정은 "처음 추천값" 역할만 남긴다.

### 현재 상태 점검

| 구분 | 지금 | 개인 프로젝트로 쓰려면 |
|---|---|---|
| 로그인 · 세션 · 자동 로그인 | 사람마다 따로 | 그대로 사용 |
| 기록 데이터 (일정 · 목표 · 체크리스트 · 아이디어 · 숙원 등) | 사람마다 따로 서버에 저장 (store_snapshots) | 그대로 사용 |
| 숏폼 제작 데이터 · 파일 | 사람마다 따로 | 그대로 사용 (권한은 관리자가 켬) |
| 웹 푸시 · 앱 서버 푸시 | 사람마다 따로 | 그대로 사용 |
| 새 회원 첫 화면 | 예시 일정만 비운 기본 데이터로 시작 | **본인이 고르는 시작 과정** 필요 |
| 볼 수 있는 영역 (개인 · 근로 · 사업) | **관리자가** 회원 관리에서 지정 | **본인이** 고르기 |
| 보이는 카테고리 | **관리자가** 검수한 카테고리만 (전체 공통 1벌) | **본인이** 고르기 · 숨기기 · 추가 |
| 영역 · 카테고리 이름 | 코드에 고정 | 본인이 이름 바꾸기 |
| 가입 | 초대 코드 / 공개 / 막기 (관리자가 정함) | 그대로 + 가입 직후 안내 |
| 비밀번호 잊었을 때 | 관리자가 VPS 에서 직접 바꿔 줌 | **이메일로 스스로 재설정** |
| 탈퇴 · 내 데이터 지우기 | 관리자가 VPS 에서 삭제 | **본인이** 설정에서 |
| 내 데이터 내려받기 | 백업(내보내기)으로 가능 | 그대로 사용 |
| AI (목표 · 아이디어 · 숙원) | 서버 키 1개를 모두가 공유, 하루 한도는 서버 메모리 (재시작하면 초기화) | **사람별 사용량 기록 · 한도**, 원하면 **개인 키** |
| 관리자 이메일 | 화면 코드(JS)에 들어 있어 누구나 볼 수 있음 | **서버에서만 확인**하도록 빼기 |

## 2. 안건

1. 1단계 — 가입 · 계정을 스스로 관리하게 (비밀번호 재설정 · 탈퇴)
2. 2단계 — 첫 시작 과정 (내 영역 · 카테고리 · 예시 데이터 고르기)
3. 3단계 — 내 구조 꾸미기 (영역 · 카테고리 이름 바꾸기 · 추가 · 숨기기)
4. 4단계 — AI 사용량 · 비용을 사람별로
5. 5단계 — 개인정보 · 보안 정리
6. 6단계 — 운영 (사용량 보기 · 용량 한도 · 서버 확장 기준)

---

## 3. 안건 별 주요 내용

### 1단계 — 가입 · 계정을 스스로 관리하게

- **왜**: 지금은 비밀번호를 잊거나 탈퇴하려면 관리자가 VPS 에서 명령을 쳐야 한다. 회원이 늘면 관리자 일이 된다.
- **만들 것**
  - 로그인 화면 "비밀번호를 잊으셨나요?" → 가입한 이메일로 재설정 링크(30분 유효, 한 번만 사용) → 새 비밀번호 → 모든 기기 로그아웃
  - 설정 › 계정 "탈퇴하기": 비밀번호를 한 번 더 확인 → 백업 파일을 내려받을지 묻기 → 계정 · 데이터 · 숏폼 파일 · 푸시 기기 모두 삭제
  - 가입 직후 환영 화면 (2단계 시작 과정으로 연결)
- **직접 하실 것**
  - 이메일 발송 서비스 하나 정하기 (예: Resend · 네이버 메일 SMTP · Gmail 앱 비밀번호). 키는 기존처럼 VPS 에서 `jcal-admin` 명령으로 넣기
  - 발신 이메일 주소 정하기
- **서버 업데이트**: 필요 (DB 표 추가: 재설정 토큰)
- **완료 기준**: 관리자 도움 없이 비밀번호 재설정 · 탈퇴가 된다

### 2단계 — 첫 시작 과정

- **왜**: 지금 새 회원은 관리자가 고른 영역 · 카테고리 화면으로 바로 들어간다. 무엇부터 해야 할지 모른다.
- **만들 것** (처음 로그인할 때 한 번, 설정에서 다시 하기 가능)
  1. 어떤 영역을 쓸지: 개인 · 근로 · 사업 중 고르기
  2. 영역마다 쓸 카테고리 고르기 (관리자가 검수한 카테고리는 "추천"으로 미리 체크)
  3. 예시 데이터를 넣고 둘러볼지 / 빈 상태로 시작할지
  4. 알림 켜기 (웹 푸시 · 앱)
  5. 이미 있는 시작 과정으로 이어 주기: 체크리스트 추천, 목표 To do AI, 아이디어 뱅크 안내
- **바뀌는 것**: 관리자가 회원마다 영역을 정해 주던 기능과, 전체 회원 공통 "검수 화면"은 **추천 기본값**으로 바뀐다. 관리자가 막고 싶은 영역이 있으면 "숨김"으로 남겨 둘 수 있다.
- **서버 업데이트**: 조금 필요 (회원이 고른 영역을 저장)
- **완료 기준**: 새 회원이 3분 안에 자기 화면을 고르고 첫 기록을 남긴다

### 3단계 — 내 구조 꾸미기

- **왜**: 사람마다 쓰는 말과 관리할 것이 다르다 (예: "사업" 대신 "부업", "건강 관리" 대신 "운동").
- **만들 것**
  - 설정 › 카테고리: 영역 이름 바꾸기, 카테고리 이름 바꾸기 · 숨기기 · 순서 · **새로 만들기**
  - 새로 만든 카테고리에도 목표 보드 · 체크리스트 · 할 일이 붙도록
  - 이름을 바꿔도 이전 기록 · 목표 · 알림이 그대로 이어지도록 (내부 이름은 그대로 두고 보이는 이름만 바꿈)
- **서버 업데이트**: 필요 없음 (회원 데이터 안에 저장)
- **완료 기준**: 다른 회원의 구조에 영향 없이 내 화면만 바뀐다

### 4단계 — AI 사용량 · 비용을 사람별로

- **왜**: 지금은 모든 회원이 관리자의 AI 키를 함께 쓰고, 하루 한도는 서버를 다시 켜면 0으로 돌아간다. 회원이 늘면 비용을 예측할 수 없다.
- **만들 것**
  - 사람별 AI 사용 기록을 DB 에 저장 (날짜 · 기능 · 횟수 · 대략 비용)
  - 회원별 한도: 기본 한도 + 관리자가 회원 관리에서 늘리기 · 줄이기 · 끄기
  - 설정 › 내 사용량: 이번 달 AI 사용 횟수 보기
  - (선택) 내 AI 키 쓰기: 회원이 자기 키를 넣으면 관리자 키 대신 그 키로 (서버에 암호화해 저장)
- **정하실 것**: 기본 한도(예: 하루 AI 20번 · 받아쓰기 30분), 개인 키 허용 여부
- **서버 업데이트**: 필요 (DB 표 추가: 사용 기록)
- **완료 기준**: 서버를 다시 켜도 한도가 유지되고, 관리자가 회원별 사용량을 본다

### 5단계 — 개인정보 · 보안 정리

- **만들 것**
  - 관리자 이메일을 화면 코드에서 빼고, 관리자 여부는 서버 응답(role)으로만 판단
  - 관리자 화면에서 회원 **기록 내용은 보이지 않게** (지금처럼 가입일 · 마지막 로그인 · 데이터 크기만)
  - 개인정보 처리방침 · 이용 안내 페이지 (무엇을 저장하고, AI 에 무엇을 보내고, 언제 지우는지)
  - 회원별 백업: 매일 서버 백업은 그대로, 회원이 설정에서 "지난 7일 중 하루로 되돌리기"
- **정하실 것**: 처리방침에 넣을 운영자 이름 · 연락처
- **서버 업데이트**: 필요 (되돌리기용 이전 버전 보관)
- **완료 기준**: 회원 화면 코드에 다른 사람의 개인정보가 없고, 관리자도 회원 기록 내용을 볼 수 없다

### 6단계 — 운영

- **만들 것**
  - 회원 관리에 회원별 데이터 크기 · AI 사용량 · 마지막 사용일 표
  - 회원별 저장 용량 한도 (예: 기록 20MB · 숏폼 파일 2GB) 와 넘을 때 안내
  - 오래 안 쓴 계정 안내 메일 (선택)
- **서버 확장 기준** (지금 VPS 1대로 충분한 범위)
  - 회원 50명 안팎까지는 지금 구조 그대로
  - 그 이상이거나 숏폼 영상 제작을 많이 쓰면: 서버 사양 올리기 · 영상 파일 저장소 분리 검토
- **완료 기준**: 관리자가 한 화면에서 전체 회원 상태와 비용을 본다

## 4. 결론

- 데이터는 이미 사람별로 나뉘어 있어서 **처음부터 다시 만들 필요는 없다.**
- 핵심은 "관리자가 정해 주던 것"을 "회원이 직접 정하는 것"으로 바꾸는 일이다: **2단계(첫 시작 과정)와 3단계(내 구조 꾸미기)가 개인 프로젝트 느낌의 중심**이다.
- 회원을 실제로 받기 전에 **1단계(비밀번호 재설정 · 탈퇴)와 5단계 중 관리자 이메일 빼기**는 먼저 해 두는 것이 안전하다.
- 권장 순서: **5단계 일부(관리자 이메일 빼기) → 2단계 → 3단계 → 1단계 → 4단계 → 6단계**

## 6. 기타

- 이 계획은 저장소 `docs/personal-workspace-plan.md` 에 있고, 단계를 끝낼 때마다 표의 상태를 고친다.
- 진행 상태
  - 2026-11-20 · 계정별 데이터 분리 보강 + 5단계 일부(관리자 이메일 빼기) 완료
    - 같은 기기에서 다른 계정으로 로그인하면 이전 계정의 기록 · API 키 · 원드라이브 로그인을 서버에서 받기 전에 바로 비움 (인터넷이 끊겨도 안 보임)
    - 로그아웃할 때 원드라이브 로그인도 지움
    - 웹 푸시를 받는 기기는 로그인한 계정으로 다시 등록 → 이전 계정 알림이 오지 않음
    - 관리자 여부는 서버 응답(role)으로만 판단, 화면 코드에서 관리자 이메일 제거
    - 서버 시험 추가: 정리된 표(47개)도 사용자끼리 분리 · 같은 기기 푸시 구독이 새 계정으로 옮겨감
- 이미 쓰고 있는 관리자 계정의 데이터 · 화면은 바뀌지 않는다. 바뀐 화면은 새 회원과, 원하는 기존 회원에게만 적용된다.
- 키 · 비밀번호는 지금처럼 채팅이나 저장소에 넣지 않고 VPS 에서 `jcal-admin` 명령으로만 넣는다.
